# Лабораторная работа №1 — абстрактные структуры данных

Вариант дерева **3: Complete Binary Tree**. Линейные структуры реализованы
вручную на C++ и Go; дерево — только на C++, согласно [ТЗ](docs/LR1_2026.pdf).
Сохранено исходное разбиение на `c++/` и `go/`, отдельный модуль для каждой
структуры и диспетчер команд в `main`.

## Сборка и проверка

Нужны Linux/POSIX, компилятор C++17, GNU Make, Go >= 1.23 и Python 3
(для интеграционных тестов). Внешних библиотек у программ нет.

```sh
make -j2 all
make test
```

Если компилятор Go установлен отдельно, задайте `make GO=/путь/к/go all`.
В подготовленной облачной среде Makefile автоматически использует
`/workspace/.tools/go/bin/go`. Системная команда `/usr/bin/go` в этой среде —
игра, а не компилятор. Автоматическая загрузка зависимостей Go отключена:
проект использует только стандартную библиотеку.

`make test` запускает C++ тесты с AddressSanitizer/UndefinedBehaviorSanitizer
и проверкой утечек, три модельных теста Go, `go vet` и интеграционные тесты
CLI. В песочницах с ограничением `ptrace` LeakSanitizer нужно запускать
в разрешённом режиме без этого ограничения; не отключайте проверку утечек.

## Запуск

Один вызов программы выполняет одну команду. Следующий вызов заново читает
сохранённый файл. Индексы начинаются с нуля. Имена и строковые значения —
непустые токены без пробельных символов. Кириллица поддерживается.

```sh
./build/dbms-cpp --file example.data --query 'MPUSH marks 10'
./build/dbms-cpp --file example.data --query 'MINSERT marks 0 5'
./build/dbms-go --file example.data --query 'PRINT marks'
# 5 10

./build/dbms-cpp --file example.data --query 'TINSERT tree 40'
./build/dbms-cpp --file example.data --query 'TINSERT tree 10'
./build/dbms-cpp --file example.data --query 'TINSERT tree 70'
./build/dbms-cpp --file example.data --query 'TISCOMPLETE tree'
# TRUE
./build/dbms-cpp --file example.data --query 'PRINT tree'
# ROOT: 40
#   L: 10
#   R: 70
```

Ключи дерева — знаковые 32-битные целые числа. Дубликаты разрешены:
это обычное полное двоичное дерево, без упорядочивания ключей.
Вставка занимает первое свободное место в обходе по уровням.
`TISCOMPLETE` проверяет, что все уровни, кроме последнего, заполнены,
а последний заполнен слева направо. Для пустого дерева результат `TRUE`.
Согласно ТЗ, **вместо удаления реализована проверка полноты**; `TDEL`
для варианта 3 отсутствует.

## Команды

В таблице `p` означает префикс `F` или `L`, `name` — имя контейнера,
`target` — значение **первого** подходящего узла, `value` — новое значение.
Добавляющие команды создают отсутствующий контейнер автоматически.
Для явного создания пустого контейнера используются команды `*CREATE`.

| Структура | Команды |
|---|---|
| Общие | `HELP`, `PRINT name` |
| Создание | `MCREATE name`, `FCREATE name`, `LCREATE name`, `SCREATE name`, `QCREATE name`; C++: `TCREATE name` |
| Массив | `MPUSH name value`, `MINSERT name index value`, `MGET name index`, `MSET name index value`, `MDEL name index`, `MLEN name`, `MREAD name` |
| Списки | `pPUSH name value`, `pINSERTHEAD name value`, `pINSERTTAIL name value`, `pINSERTBEFORE name target value`, `pINSERTAFTER name target value` |
| Удаление из списков | `pDELHEAD name`, `pDELTAIL name`, `pDELBEFORE name target`, `pDELAFTER name target`, `pDEL name value`, `pREMOVE name value` |
| Чтение списков | `pGET name value`, `pFIND name value`, `pREAD name [FORWARD\|REVERSE]` |
| Стек | `SPUSH name value`, `SPOP name`, `SGET name`, `SREAD name` |
| Очередь | `QPUSH name value`, `QPOP name`, `QGET name`, `QREAD name` |
| Дерево, только C++ | `TINSERT name key`, `TGET name key`, `ISMEMBER name key`, `TISCOMPLETE name`, `TREAD name` |

`PUSH`, вставка и замена возвращают записанное значение; удаление/`POP` —
удалённое. `FIND` возвращает индекс первого совпадения или `-1`.
`GET` списка возвращает найденное значение либо ошибку.
`TGET`/`ISMEMBER` возвращают `TRUE`/`FALSE`.
`SGET` и `QGET` читают без удаления. `PRINT`/`READ` пустого контейнера
выводят `(empty)`. Ошибки выводятся в stderr с кодом завершения 1.

## Хранение данных

Текстовый формат: число контейнеров, затем для каждого `тип имя размер`
и значения, разделённые пробелами/переводами строк. Вывод идёт в порядке
имён контейнеров. Стек записывается от вершины; при загрузке порядок
восстанавливается. Дерево записывается **по уровням**, что сохраняет форму,
порядок ключей и повторения после повторного запуска.

Go умеет читать и сохранять блоки дерева без изменений, чтобы операции
над линейными структурами не удаляли дерево из общего файла. Создание,
изменение и вывод дерева выполняются C++ программой.

Отсутствующий файл означает пустую базу. Повреждённый файл вызывает ошибку.
Изменения записываются во временный файл в том же каталоге и затем
заменяют исходный; неуспешный запрос и команды чтения его не переписывают.
Каталог должен существовать. Одновременное изменение одной базы несколькими
процессами не поддерживается. Формат старого АВЛ-проекта не содержит метки
варианта: при переносе старых данных T-блок будет интерпретирован как BFS
дерева варианта 3; для новых работ используйте новый файл.

## Файлы

- `c++/`: массив, односвязный/двусвязный списки, стек, очередь и дерево.
  Имена `quene.*` и `value3.*` сохранены для совместимости со структурой
  исходного проекта; `value3.*` теперь содержит Complete Binary Tree.
- `go/`: пять линейных структур, CLI, модуль и модельные тесты.
- `tests/`: C++ проверки инвариантов и Python тесты CLI.
- [docs/REPORT.md](docs/REPORT.md) и `Отчёт_ЛР1.docx`: переработанный отчёт,
  Big O, достоинства/недостатки, схемы и фактические контрольные примеры.
- `docs/evidence.txt`, `docs/evidence-*.png`: вывод контрольных запусков
  и его визуальное представление.
- `docs/requirements.md`: сверка реализации с каждым пунктом ТЗ.

Чтобы пересоздать отчёт после изменений, выполните `make all`, затем
`python3 tests/capture_examples.py` и `python3 docs/build_report.py`.
Для последней команды нужны пакеты из `docs/requirements-report.txt`
и шрифт DejaVu Sans Mono; программы C++/Go от них не зависят.
